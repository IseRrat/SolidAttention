# 测试与评测计划

## 正确性

- 布局：多 dtype、不同 head 维度、满块/尾块的 K/V encode-decode round-trip；比较交错与独立布局的 attention 输出。
- 选择：init/local 边界、窗口重叠去重、top-k 并列、预算取整、GQA/MQA、位置掩码和未来 token 排除。
- 预取：无历史、全命中、部分命中、全错、乱序完成；同一输入下与关闭预取的输出及实际选块集合一致。
- 槽位：PINNED 不覆盖，generation 拒绝迟到事件；容量不足有显式结果。
- I/O：短读、读写失败、取消和回写未完成时读取；不能使用部分写入的块。

## 模型级验证

固定模型、tokenizer、量化、种子、prompt 和生成参数，先比较全内存与同步 SSD 路径，再比较同步稀疏与预取/调度版本。无稀疏时要求数值结果在确定的浮点容差内一致；有稀疏时报告任务准确率差异和样例失败，而不是要求与全注意力逐 token 完全相同。长上下文检索任务至少覆盖英文和中文目标定位，增加多轮对话或摘要任务检验位置相关行为。

## 性能与消融

每个配置记录模型哈希、代码提交、CPU/GPU、DRAM/VRAM、SSD、内核、驱动、后端、上下文长度、块大小、预算、I/O 配置和温度/缓存状态。按全内存、全量 SSD、SSD+稀疏、加交错、加预取、加调度顺序比较。分别记录 prefill 与 decode；单请求低并发是主场景，额外测试并发与 SSD 干扰。逐 token 延迟给出分布和重复运行波动，不只报最大加速。内存同时报峰值与稳定态，SSD 报读取字节和请求数，准确率与性能同表呈现。

## 阶段门槛

阶段 1 通过布局、选择和 SSD 读写正确性；阶段 2 通过所有预取错误纠正测试；阶段 3 通过并发/故障注入与串行对照；阶段 4 形成可复跑的实验报告。任一阶段准确性回归，应先定位回归再讨论性能收益。

## 可执行验收样例

| 场景 | 输入构造 | 必须观察到的结果 |
| --- | --- | --- |
| 交错布局 | 两个 KV head、非整块尾部、K/V 使用可辨识递增值 | 解码后每个 `(layer, head, position)` 的 K/V 与输入逐元素一致，padding 不参与注意力 |
| 选块重叠 | init 与 local 在短上下文交叠，selected 候选含相同块 | 逻辑块只出现一次，实际有效 token 不超过配置预算 |
| 预取全错 | 将上一轮 selected 全部替换为本轮不会选中的块 | 补读完成后实际块集合和输出与禁用预取相同，错误预取槽不残留旧 ID |
| 乱序 I/O | 延迟旧槽位读取完成事件，先复用槽位并增大 generation | 旧事件被拒绝，不可把新槽位标为旧块 READY |
| 在用槽位 | attention 持有 PINNED，同时发出下一层预取 | 预取等待或使用其他槽位；attention 输出不变 |
| 写失败 | 当前 decode token 的新 KV 写入返回错误 | 块不可标为可读，后续推理显式失败并记录块 ID |

每条测试保留输入、预期逻辑块、事件轨迹与输出摘要。性能数据只能在同一版本通过上述正确性门槛后采集。
