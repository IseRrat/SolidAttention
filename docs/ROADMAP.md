# 实施大纲

目标顺序是先得到可比较、可复现的基线，再逐项实现论文机制，最后开展创新实验。每阶段以验收条件结束，而不是以代码量结束。

## 阶段 0：实验与接口准备

**工作**：固定论文版本和术语；选定 llama.cpp 版本、模型、Linux/CUDA、SSD 与内存限制；记录硬件和软件配置；定义生成速度、逐 token 延迟、P50/P99、KV 驻留内存、SSD 读写量和准确率的测量方法。搭建全内存和朴素 SSD offload 基线，准备同输入、同精度、同上下文预算的对比配置。

**产物**：可重复运行的基线命令与结果表、版本锁定、环境记录、最小用例。**验收**：固定随机种子和参数下输出可复查；计时边界、内存统计口径明确。未完成基线时不报告加速倍数。

## 阶段 1：正确的分块与 SSD KV 路径

**工作**：按 layer/head/token 定义块 ID、位置映射和元数据；实现 init、local、selected 三类块的预算分配与动态选择；保留完整 KV 于 SSD，缺块同步加载；确保 K/V 成对、位置编码及 attention mask 正确。先使用简单布局与同步 I/O，随后实现 token 级 K/V 交错布局，比较传输次数、读放大和准确率。代表向量的构造需在适配的模型上按论文引用的 InfLLM 方案核实。

**产物**：端到端单请求 decode、块选择记录、布局单测和准确率基线。**验收**：随机访问及故障注入不产生错位或脏读；短上下文与全内存路径一致到预设容差；长上下文任务相对参考实现的准确率损失可量化。

## 阶段 2：历史预取与纠错

**工作**：每层保存上一 decode 轮 selected 块列表；init/local 块确定性预取；异步发出预测块读取；正式选择后识别命中、遗漏和错误预取；在安全槽位中加载遗漏块，更新逻辑块到物理槽位映射。加入冷启动、预算不足、I/O 错误和预取命中率统计。

**产物**：预取器、槽位状态机、命中/纠错轨迹。**验收**：在预取全错和命中两种极端情况下结果与无预取路径一致；任何在用槽位不会被覆盖；输出选择集合不受预测结果影响。

## 阶段 3：SSD-aware 微任务调度

**工作**：以依赖图表达 q/kv projection、select、prefetch、miss load、attention、store；将 miss load 与 kv projection 重叠；按关键路径和最晚开始时间安排就绪任务；把非关键回写和预取复用同步点。先建立串行调度参考，再逐步打开异步执行。

**产物**：调度器、事件轨迹、并发压力测试。**验收**：依赖和缓冲区生命周期无违规；输出与串行版本一致；单 token I/O 等待时间、同步次数和临界路径时间可测。

## 阶段 4：论文复现评测

**工作**：复现核心消融：朴素 offload、offload+稀疏、交错布局、加预取、加调度；测试不同上下文长度、块大小、预算、SSD 干扰与模型。使用长文本检索及生成质量任务验证准确率，报告硬件差异和无法完全匹配的设置。

**产物**：实验脚本、原始结果、图表与复现报告。**验收**：每项结论可追溯到配置和原始数据；论文数字与本机结果分列；重复运行给出波动范围。

## 阶段 5：创新研究

先以阶段 4 的瓶颈数据选题，再选择一项做独立消融：例如基于历史命中率与 SSD 队列深度的自适应预取、按块重要性/读成本联合预算分配，或面向资源受限设备的缓冲区调度。每项创新均保留论文策略作对照，单独报告准确率、延迟、内存和写放大。未验证前这些只是研究假设。
